# Developer access and ticket fees

Developer identity is the server-verified OTP account `freddie@mullens.com`. This is not an assignable club staff role and club role changes do not revoke or grant it. `/developer/` reports payments and sales for rolling 24-hour, 48-hour, 7-day and 30-day periods. Card and wallet parts of one checkout count as one payment. Dates use UK time. Figures reflect successful/refunded transaction records, not Stripe payout balances; refunds are associated with the original payment period.

Customer support can start from the developer dashboard or Contacts → View → View as customer. A reason is required. A separate opaque HttpOnly cookie identifies a 20-minute support session bound to the developer's existing login session. The original developer identity remains authenticated. Customer view strips all staff/developer privileges, including when the target is also staff. Start/end and write attempts are recorded without copying request bodies or medical information. The visible banner ends support access and returns to the developer dashboard. Expired access blocks writes rather than applying them to the developer's own account. The cookie remains long enough to display this expired-access gate; it does not extend the database session's 20-minute expiry. No customer OTP is sent.

The platform commission on newly prepared card baskets is the rounded 2.5% of the card amount plus 20p for each resulting activity ticket or party booking. Packages count their resulting individual session tickets. The commission is capped at the amount actually paid by card, as Stripe cannot deduct a larger application fee. Wallet-only orders incur no Stripe application fee. Awards retain their existing single 20p checkout component. The customer total is unchanged; this is deducted through Stripe Connect. Existing/open checkout fee snapshots are retained on retries and are not recalculated retroactively.

Apply `database/ticket-service-fees.sql` after `database/wallet-successful-checkout.sql`. `database/developer-support.sql` creates server-only RLS-protected support/audit tables. Both changes were applied on 15/10/2026. The ten-ticket transaction test runs inside a rollback and calls no external payment or email provider. Additional authorization, expiry, cookie, metrics and role tests are in `tests/developer-support.test.cjs`.
